# 15 — DICE TAPE

**TIER:** CORE (rules) / REF (data) | **DEPENDS:** 01

---

## Rules

1. The tape holds **720 rows** of pre-rolled values: `idx | d100 | d20 | d6`. Columns were generated independently from a fixed seed (20261010) and are fixed for this build. Rows 1–240 are identical to the earlier 240-row tape, so older saves stay valid.
2. The Save Block keeps `tape_ptr` (1–720). **Every roll consumes exactly one row**, using the column the rule calls for (d100, d20 or d6). Then the pointer advances by one.
3. **No rerolls, skips, peeks, or substitutions, and no row is used twice.** Hidden rolls (TALA claim truth, NPC secret checks, infection chance, Turn Time) consume rows too.
4. Every roll notice cites die and row: `d20[T41]=14`. The HUD shows `PTR` = the last row used.
5. **Derived dice:** d12 = ((d100 − 1) mod 12) + 1 (≈1% bias accepted) · d10 = last digit of the d100 (0 = 10) · d8 = ((d20 − 1) mod 8) + 1.
6. **Wrap rule:** after row 720, return to row 1 for **Pass 2** and apply this transform to every value read: `d100' = ((d100 + 36) mod 100) + 1` · `d20' = ((d20 + 6) mod 20) + 1` · `d6' = ((d6 + 2) mod 6) + 1`. Pass 3 repeats the transform on top of Pass 2. Record `tape_pass` in the Save Block. A 90-day campaign normally stays inside Pass 1 (combat uses about 3 rows per round, exploration about 1 per turn).
7. If a rule calls for more than one die in the same moment (a bite location plus an infection check), consume rows **in the order the rules list them**.

## Auditing (the tape is auditable, not tamper-proof)

Claude can see the whole table, so the tape cannot *prevent* a bad roll. What it does is make every roll **checkable**:
- `/tape` prints the pointer and the last 5 rolls with row numbers.
- `/audit` prints every roll since the last audit as `T<row> <die> = <value>`. Compare against the table below, or run the offline checker: `python3 tools/tape_check.py rolls.txt` (paste your roll notices into `rolls.txt`). It flags wrong values, repeated rows, and rows used out of order.
- A mismatch is a **tape violation**: the GM must correct it once, restate the affected outcome, and continue.
- The table checksum lets you detect an edited file: **sum(d100) = 35757 · sum(d20) = 7487 · sum(d6) = 2598** (720 rows).
